# Domain Workflow: Side Project Momentum

## 1. Goal Compilation
- **User Prompt:** "I want to consistently work on my side project every weekend."
- **Derived Identity:** *"I am an independent software creator."*
- **Habit Title:** Weekend Project Sprint
- **Behavior Definition:** Advance features, write tests, or resolve backlog items on personal software project.
- **Normal Target:** 90 minutes of project engineering.
- **Minimum Action (2-Minute Rule):** Open project kanban/backlog and review the top 3 items for 2 minutes.
- **Cue Type:** `time`
  - Frequency: `weekly` (Saturday)
  - Cue Description: "Saturday morning after breakfast at 10:00"
  - Cue Time: `10:00` wall-clock time

## 2. Notification & Reminder Policy Application
- **Scheduled Time:** Saturday `10:00`.
- **Policy Check (`rulebook/rules/reminders.md`):**
  - Falls outside Quiet Hours (`22:00`–`08:00`). ✅ Permitted.
  - Saturday 10:00 is within weekly frequency bounds. ✅
  - Notification action: `[Start Sprint]` `[Review Backlog (2m)]`.

## 3. Missed Habit Recovery Scenario
1. **Saturday (Missed):**
   - User travels or attends social event; Saturday passes without working on project.
   - At end of Saturday, habit transitions to `status: 'recovery'`.
2. **Sunday (Recovery Protocol):**
   - Because weekly frequency would otherwise delay next action by 7 days, Never-Miss-Twice immediately schedules a Sunday recovery window!
   - Sunday morning widget surfaces: *"Never Miss Twice: Review project backlog for 2 minutes."*
   - User spends 2 minutes reviewing the top issue on Sunday morning and taps complete.
   - Momentum is preserved without waiting an entire week.
