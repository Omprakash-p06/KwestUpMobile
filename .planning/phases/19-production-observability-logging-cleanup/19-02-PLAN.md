**Phase:** 19 of 19 (Milestone 2 Final Phase)

---

## 1. Goal

Set up structured crash boundaries and diagnostics for release builds by implementing a top-level React `ErrorBoundary` component adhering to the `19-UI-SPEC.md` design contract. The boundary will catch unhandled rendering exceptions, log forensic stack traces to `logger.js`, and display a themed recovery interface reassuring users of data safety with one-tap retry and diagnostic report copying.

---

## 2. Tasks

### Task 1: Install `expo-clipboard` & Implement `src/components/ErrorBoundary.js`
- Install `expo-clipboard@~7.0.1` as a dependency.
- Create `src/components/ErrorBoundary.js` as a React class component implementing `getDerivedStateFromError` and `componentDidCatch`.
- When an error occurs:
  - Invokes `logger.error("Unhandled React Error:", error?.message, errorInfo?.componentStack)`.
  - Stores `error` and `errorInfo` in component state.
- Implement the fallback UI strictly adhering to `19-UI-SPEC.md`:
  - **Backdrop & Container:** Uses LiquidGlass dominant surface (`#0F172A` dark / `#F8FAFC` light), 2xl vertical inset, lg padding.
  - **Error Card:** Secondary surface (`#1E293B` dark / `#FFFFFF` light) with rounded corners and border.
  - **Header Icon:** `MaterialCommunityIcons` `alert-circle-outline` in destructive red (`#EF4444`).
  - **Display Title:** "Something Went Wrong" (24px bold).
  - **Reassurance Copy:** "KwestUp encountered an unexpected error. Your notes, tasks, and data remain safe on your device." (14px regular).
  - **Primary CTA:** "Try Again" button with `#6366F1` indigo accent that resets error state (`hasError: false, error: null`) to allow re-render.
  - **Secondary CTA:** "Copy Error Report" button that formats sanitized diagnostics (Platform, OS version, App version, timestamp, error stack, component trace, and recent breadcrumbs from `logger.getRecentLogs()`), copies to clipboard using `Clipboard.setStringAsync` (with fallback to `Share.share`), and shows a brief confirmation toast: "Error report copied to clipboard".
  - **Collapsible Toggle:** "View Diagnostic Details" / "Hide Diagnostic Details" button revealing sanitized error message and component trace in a monospace code box.

### Task 2: Mount ErrorBoundary at Application Root in `App.js`
- Import `ErrorBoundary` in `App.js`.
- Wrap the main application container and providers (`TaskProvider`, `VaultProvider`, `BillingProvider`, `BirthdayProvider`, `NavigationContainer`) inside `<ErrorBoundary currentTheme={currentTheme}>`.
- Verify that any unhandled exception in navigation, theme providers, or screen components is captured before reaching native process crash handlers.

### Task 3: Unit Test Suite for ErrorBoundary (`__tests__/unit/errorBoundary.test.js`)
- Author `__tests__/unit/errorBoundary.test.js`:
  - Verify normal child components render without error boundary interruption.
  - Verify component catches a child render exception and transitions to the recovery screen.
  - Verify heading "Something Went Wrong" and reassurance copy are displayed.
  - Verify "Try Again" button press resets component state and attempts to re-render children.
  - Verify "Copy Error Report" button invokes `Clipboard.setStringAsync` (or `Share.share`) with formatted diagnostics containing error message and `logger.getRecentLogs()` breadcrumbs.
  - Verify diagnostic details section toggles between hidden and visible.
